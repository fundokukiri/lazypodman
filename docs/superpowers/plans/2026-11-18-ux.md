# Phase 3 — Events, multi-select, palette: implementation plan

> **For agentic workers:** steps use `- [ ]`. Execution method: **native** (one agent,
> this session), same rhythm as the pods, healthcheck and kube batches.

**Goal:** Add a live `podman events` tab, container multi-select and a `ctrl+p`
command palette without touching the socket backend or renumbering panels.

**Spec:** `docs/superpowers/specs/2026-11-18-ux-design.md`

**Status:** all tasks done and committed (`b601ed5` events, `1969c4c` multi-select +
palette). Manual checklist lives in `TEST.md` sections D–F.

## Global constraints

- No podman call on the UI goroutine; streaming tasks use `exec.CommandContext`.
- New strings only in `pkg/i18n/english.go`; other languages fall back.
- No keybinding conflicts: check `docs/keybindings/Keybindings_en.md` and add a test
  that each new key is bound exactly once.
- Degrade with a message, never a panic: missing CLI, no selection, removed item.
- Do not claim real-Podman verification; synthetic tests until `TEST.md` is run.
- Every task ends green: `gofmt -s -l main.go pkg/ scripts/`,
  `GOFLAGS=-mod=vendor go vet ./pkg/...`, `go test ./...`,
  `golangci-lint run ./pkg/...`, cheatsheet `check`.

## Review Focus

1. Switching away from the Events tab must kill `podman events` (no orphan process).
2. Bulk stop/restart/pause/remove must never run on an empty selection, and the
   confirmation count must equal the number of operations attempted.
3. A marked container removed by a refresh must silently leave the selection.
4. The palette must call the existing handlers, not re-implement them.
5. No new key may shadow an existing one, in any panel or in a popup.

### Task 2: multi-select

change), and no handler reads the panel selection directly anymore.
